# Full review and SOTA reset — 2026-07-15

## Verdict

The repository is a strong experimental harness, but it is not yet evidence for
the stated phased-agent thesis. The core measurement abstractions are useful:
provider-independent clients, protocol backends, context policies, typed run
records, pricing, traces, replayable phase nodes, and several real experiment
families. The current scientific sequence is the problem.

Today the phased system consists of one read-only `localize` node. There is no
localize → repair → test → verify agent, no minimal-agent control, and no
held-out config router. The recent config-arm script measured an in-sample
per-task oracle upper bound on localization and described it as evidence for a
per-phase bandit. That cannot establish either deployable routing or cross-phase
heterogeneity.

The program should continue, but with a stricter first question:

> Under the same backbone, task set, budget, and harness version, does a fixed
> phased scaffold or an adaptive scaffold outperform a minimal free-loop agent?

Only optimize per-phase config bundles after the scaffold earns its complexity.

## What is genuinely strong

- The experiment/core separation is clean. Domain contracts and trials sit
  outside the shared sweep, budget, trace, and reporting machinery.
- `ModelHandle = ModelClient + ToolBackend + ContextPolicy` exposes meaningful
  intervention axes instead of burying them in agent code.
- `SessionTrace` and `PhaseNode` are a good substrate for paired counterfactual
  runs, phase reward attachment, and later checkpoint/fork experiments.
- The repo records cost, latency decomposition, usage, transcripts, failures,
  and config provenance. That is substantially better than a pass-rate-only
  benchmark script.
- The code-editing, tool-selection, and localization studies contain useful
  empirical observations even though several headline samples are small.

## Where the evidence falls short

| Area | Current state | Consequence |
|---|---|---|
| Agent capability | One localization phase; no end-to-end SWE agent | Cannot compare against coding-agent SOTA |
| Scaffold control | No minimal bash/free-loop baseline | Cannot attribute gains to phase structure |
| Workflow choice | Fixed phases assumed | Adaptive routing may skip or reorder unnecessary work |
| Config selection | Per-task reward oracle on one phase | Optimistic ceiling, not a deployable selector |
| Router context | “Phase identity” proposed as contextual input | `config = f(phase)` is a static per-phase table, not task-adaptive routing |
| Generalization | Same tasks choose and score the best arm | Selection bias; no cross-repo or held-out estimate |
| Reward validity | Localization reward uses one gold patch | May penalize valid alternative repair sites and need not improve repair success |
| Statistical rigor | Tiny easy samples in several studies | Means and 100% pass rates are unstable; uncertainty is absent from older reports |
| Context arms | Tool-result elision is Anthropic-only | OpenAI/Google “elision” arms were duplicate no-ops |
| Reproducibility | Python version and two workspace dependencies were implicit | Fresh environments could select Python 3.14 or miss shared imports |

All four maintained unit suites passed before this change (191 tests total),
but static analysis was not enforced. Ruff found 46 maintained-source issues;
these are now cleaned and lint is part of CI. Mypy remains non-blocking and
reports 66 errors across 12 files, especially around provider SDK unions and
semantic-edit AST types; it still needs a dedicated typing pass.

## Comparison with the current frontier

### 1. A minimal agent is the required control

The official SWE-bench evaluation now uses mini-SWE-agent as a standardized
bash-only model comparison. Its control flow is deliberately small and linear,
and its maintainers explicitly recommend it as the default research baseline.
The official Verified page also warns that mini v1 and v2 results are not
necessarily comparable, so every result must pin the scaffold release.

Sources: [SWE-bench Verified](https://www.swebench.com/verified.html),
[mini-SWE-agent](https://github.com/SWE-agent/mini-swe-agent).

Implication: Agent Bench should import or reproduce a pinned mini-style loop
before claiming that architectural phases help. The baseline must use the same
model, reasoning setting, dollar/step cap, environment, and task order.

### 2. Adaptive workflows have overtaken “always run fixed phases” as the main
scaffold hypothesis

icat-agent routes well-specified issues toward parallel patch/validation and
poorly specified issues toward preliminary exploration, using event-based
handoffs instead of one shared context. Its paper reports same-backbone gains on
both Verified and SWE-bench Pro. Whether those exact results reproduce is an
empirical question, but the design makes a forced localize → repair → test →
verify pipeline a treatment, not the default truth.

Source: [icat-agent paper](https://arxiv.org/abs/2606.25514).

Implication: the first scaffold experiment needs three arms:

1. minimal free loop;
2. fixed, architecturally enforced phases;
3. adaptive workflow chosen from deploy-time issue/state features.

### 3. Per-module and sequential model selection is no longer an empty niche

The closest work now includes:

- LLMSelector, which chooses models per compound-system module and tests a
  monotonic module-quality assumption;
- Optimas, which learns globally aligned local reward functions for heterogeneous
  component optimization;
- a neural contextual bandit that explicitly selects a sequence of LLMs for
  dependent pipeline subtasks while accounting for downstream effects.

Sources: [LLMSelector](https://arxiv.org/abs/2502.14815),
[Optimas](https://arxiv.org/abs/2507.03041),
[Neural Bandit Based Optimal LLM Selection for a Pipeline of Tasks](https://arxiv.org/abs/2508.09958).

Implication: the defensible delta is narrower than “nobody configures models per
phase.” The potentially ownable contribution is:

> held-out, task/state-adaptive routing over a joint
> model × prompt × context/handoff bundle at verifiable software-engineering
> boundaries, with explicit downstream-alignment and transfer tests.

### 4. Verified alone is no longer enough

Verified remains useful for comparable, human-filtered evaluation, but the
minimal-agent results are already strong and harness-version-sensitive.
SWE-bench Pro provides 1,865 longer-horizon problems from 41 repositories and is
the better place to look for scaffold headroom. Use its public/open subset for
development and preserve a held-out repository split; do not tune against a
public leaderboard.

Sources: [SWE-bench leaderboard](https://www.swebench.com/),
[SWE-bench Pro](https://arxiv.org/abs/2509.16941).

### 5. Traces should drive improvement, not only record reward

Socratic-SWE turns recurring trace failures and successful patterns into skills
that guide executable task generation. Agent Bench already has the trace and
failure-taxonomy substrate needed for a lighter version of this feedback loop.

Source: [Socratic-SWE](https://arxiv.org/abs/2606.07412).

## New plan of record

### Gate 0 — freeze the evaluation contract

- Pin Python, scaffold commit/release, model snapshot/alias, provider API,
  reasoning effort, temperature behavior, environment image, task IDs, and
  budget.
- Report resolved rate, cost per task, cost per resolved task, wall time, model
  turns, and failure mode.
- Use paired same-task comparisons, repository-grouped train/validation/test
  splits, and task-bootstrap confidence intervals.
- Preserve historical model/config entries; add new families rather than
  rewriting old baselines.

### Gate 1 — scaffold value experiment

Build the smallest end-to-end agent capable of editing and testing, then compare
the three scaffold arms above on the same hard Verified pilot and SWE-bench Pro
public pilot. Start small to validate the harness; determine the final sample
size from the observed paired variance rather than choosing it from cost alone.

Proceed only if the phased or adaptive scaffold is statistically better on
resolved rate, or Pareto-better on resolved rate and cost. If the minimal loop
wins, keep the phase trace as instrumentation and stop forcing phase control.

### Gate 2 — validate phase rewards downstream

At each boundary, fork from the same state and measure whether a higher local
reward predicts greater downstream task success. In particular, regress repair
success on localization reward while controlling for task/repository. If the
local metric is weakly aligned, learn or redesign the reward before optimizing
it.

### Gate 3 — config routing, with the right baselines

On at least three operational phases, compare:

1. best homogeneous end-to-end config;
2. best static per-phase table, `config = f(phase)`;
3. learned held-out router, `config = f(phase, task, state)`;
4. per-task reward oracle upper bound.

Choose and tune on train/validation repositories, report once on held-out
repositories, and include a cost-constrained frontier. A positive oracle gap
only authorizes router research; only the held-out learned-router result
supports a routing claim.

### Gate 4 — handoff and trace-derived improvement

Treat the handoff brief as an explicit config action and reward it by downstream
repair success. Then cluster trace failures into candidate skills/prompts and
validate each candidate on held-out tasks before promotion.

## Changes made in this review

- Migrated the native OpenAI client from Chat Completions to the Responses API,
  including manual replay of encrypted reasoning items, flat Responses tool
  schemas, cache-aware token accounting, and streaming TTFT measurement.
- Added the current GPT-5.6 family and prices while retaining historical model
  IDs and prices.
- Reframed `run_config_arms.py` as an oracle-gap diagnostic, added a paired
  task-bootstrap interval, moved its default sample to hard Verified tasks, and
  stopped creating context-policy arms that are known no-ops for a provider.
- Fixed context-elision measurement: content replacement now counts even when
  message count is unchanged, and serialized characters elided are recorded.
- Made empty localization gold sets fail instead of passing vacuously.
- Removed the duplicate code-editing task dataclass, declared missing workspace
  dependencies, pinned Python 3.12, cleaned maintained-source lint, and added CI
  lint enforcement.
- Added a hermetic Gate 1 MVP with one common execution contract for a versioned
  minimal free loop, enforced fixed phases, and a frozen deploy-time adaptive
  heuristic. It emits phase traces, separates public test reward from the hidden
  final oracle, and reports paired task-bootstrap effects. Scripted end-to-end
  tests and a client-free dry run cover the harness before paid evaluation.

## Remaining engineering risks

- A hermetic internal end-to-end agent now exists, but an official
  mini-SWE-agent-style shell control and the Verified/Pro execution environment
  are not integrated. The restorable environment/checkpoint plane also remains
  absent; current mutating-phase traces store a workspace digest only.
- OpenAI Responses is covered by offline SDK-shaped tests, not a paid live smoke
  run. A one-task live canary should precede a sweep.
- OpenAI and Google context policies still pass through unchanged; do not label
  them as context ablations until implemented.
- Type checking is not clean or enforced.
- The repository has no explicit `LICENSE`; selecting one is an owner/legal
  decision and was intentionally not inferred here.
